DESIGN PRINCIPLES

四个设计原则

全渠道一致体验

门户、图鉴、商城与会员中心共享同一套设计语言和内容模型。

内容与交易解耦

资讯、动画、商品、卡牌独立运营，又通过会员与搜索串联。

数据驱动经营

内容表现、交易转化与财务结果，被放进同一个管理驾驶舱。

安全与合规

管理端角色隔离、演示数据脱敏；生产环境遵循数据最小化原则。

IMPLEMENTATION BOUNDARY

课堂演示 vs 生产环境

把边界讲清楚，比假装拥有后端更重要。

本次实现 纯前端静态网站

所有页面、交互与数据可视化都在浏览器中运行。没有 Node/Python 业务服务，也没有数据库。网站地址由一个静态文件服务器提供。

  • HTML / CSS / Vanilla JS 静态文件
  • localStorage 保存会话、购物车、收藏与订单
  • 消费者与管理者两套前端角色视图
  • 硬编码演示账号，非生产级认证
  • 公开财务数据 + 明确标注的模拟经营数据
  • 可完全离线运行，除外部引用链接

生产扩展 云原生全渠道架构

若投入真实运营，可在保持前端体验不变的前提下，将业务能力层替换为服务化组件，并接入统一身份与数据平台。

  • API Gateway + BFF，按渠道聚合接口
  • 内容中台、商品/订单服务、会员服务
  • PostgreSQL / Redis / 对象存储 / CDN
  • OAuth 2.0 / OIDC、RBAC、审计日志
  • 数据仓库 + BI，指标口径统一治理
  • 可观测性：日志、指标、追踪与告警
KEY USER FLOW

一次完整旅程

以“发现商品并完成演示购买”为例。

STEP 01
发现

从首页或全局搜索进入资讯 / 商品 / 图鉴。

STEP 02
浏览

筛选分类、查看详情、收藏喜欢的商品或宝可梦。

STEP 03
登录

消费者登录后创建本地会话，购物车跨页面保留。

STEP 04
结算

生成演示订单并写入 localStorage，可在会员中心查看。
